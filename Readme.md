# Mailer — веб‑приложение для управления рассылками на Django

Mailer — это Django‑приложение для создания, настройки и отправки email‑рассылок, с разграничением прав доступа (пользователь vs менеджер), историей попыток отправки и базовой статистикой.

## Функциональные возможности

### Управление клиентами (получателями)
- CRUD для клиентов: добавление, просмотр, редактирование, удаление.
- Поля карточки клиента:
  - Email (уникальный)
  - Ф. И. О.
  - Комментарий

### Управление сообщениями (шаблонами писем)
- CRUD для сообщений: добавление, просмотр, редактирование, удаление.
- Поля сообщения:
  - Тема письма
  - Тело письма

### Управление рассылками
- CRUD для рассылок.
- Основные поля:
  - `start_time` (datetime, обязательно) — время начала отправки.
  - `end_time` (datetime, обязательно) — время окончания отправки.
  - `status` (строка) — вычисляется динамически: «Создана», «Запущена», «Завершена».
  - `message` (FK) — сообщение, которое будет отправлено.
  - `recipients` (M2M) — список получателей рассылки.
- Валидации:
  - `start_time` не может быть в прошлом.
  - `start_time` должен быть раньше `end_time`.
- Динамический пересчёт статуса: вызывается при просмотре объекта рассылки через `get_object()` в DetailView.

### Отправка сообщений
- Ручная отправка рассылки через интерфейс и/или через команду управления (management command).
- Логика отправки:
  1. Проверка, что текущее время находится в интервале `[start_time, end_time]`.
  2. Перебор всех получателей из связи M2M.
  3. Отправка письма через `send_mail()`.
  4. Фиксация результата для каждого получателя в таблице попыток.

### История и статистика попыток
- Для каждой попытки отправки сохраняется:
  - `attempt_time` — дата и время попытки.
  - `status` — «Успешно» / «Не успешно».
  - `server_response` — ответ почтового сервера.
  - `mailing` (FK) — связь с рассылкой.
- На главной странице отображаются:
  - Общее количество рассылок.
  - Количество активных рассылок (статус «Запущена» и текущее время в диапазоне).
  - Количество уникальных получателей (клиентов) в системе.

### Аутентификация и роли
- Регистрация с подтверждением email.
- Вход/выход из системы.
- Восстановление пароля.
- Роли:
  - **Пользователь**: CRUD своих клиентов и рассылок, просмотр своей статистики.
  - **Менеджер** (`is_staff=True`): просмотр всех данных, блокировка пользователей, отключение рассылок.

### Ограничение доступа
- Пользователи видят и управляют только своими объектами (фильтрация по полю `creator`).
- Менеджеры видят все объекты, но редактирование/удаление чужих данных ограничено логикой приложения.

### Кеширование
- Настроено серверное и клиентское кеширование для повышения производительности (настройки в `settings.py` и использование декораторов/middleware при необходимости).
